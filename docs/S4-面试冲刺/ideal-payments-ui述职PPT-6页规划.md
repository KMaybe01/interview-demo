## P2 · 项目业务全景（纯业务，零技术词）

**版式**：一句定位 + 三列场景卡 + 底部横向旅程条

- **定位句（副标题，大字）**：企业网银的**"钱袋子中枢"**——企业客户的每一笔**花钱、收钱、管钱**都要经过这套系统
- **三列场景卡（每列：场景 + 举例 + 配套）**
  - **出 · 付款**：供应商汇款（本币/跨境）、账户调拨、批量发薪、缴水电费 → 统一进**出账总账本**；配套：收款人名册、快捷模板、周期付款、**止付追回**
  - **入 · 收款**：单笔/批量托收货款 → 统一进**收款总账本**；配套：付款人档案、快捷收款模板（维护一次、处处可用）
  - **管 · 审批**：监管要求**每笔交易经办 + 复核双人把关**；可集中/就地审批，勾选多条一键批量通过/驳回
- **底部：一笔交易的完整旅程（四步横向流程）**
  `① 经办提交（财务录单）→ ② 待审批（钱不会直接扣）→ ③ 复核把关（通过/驳回）→ ④ 落地（通过=银行记账清算；驳回=记原因、可追溯）`
- **页脚**：谁在用：企业财务（提单）+ 审批人（复核）｜ 全流程满足审计要求
- **视觉**：三卡等宽 + 顶部箭头/对勾图标；旅程条用第 4 页同款节点样式，形成视觉呼应
- **口播**（50s）：
  > "先花一分钟讲清楚这个系统。它是企业网银的钱袋子中枢：企业对外付款、收款回款、以及每一笔交易的双人审批，都走这套系统。以一笔付款为例——财务提交后钱不会直接扣，先进待审池，审批人复核通过才进银行清算，驳回则记录原因全程可追溯。这满足的是监管对'经办复核'的硬性要求。"

## P4 · 核心交付：通用批量审批中枢（高潮页）

**版式**：上图下表（图占 60%，量化表占 40%）

- **主标题**：Multi-Approval 通用批量审批中枢（白话副标题：**全项目统一的"审批窗口"**）
- **中部流程图（简化为 3 步横向箭头）**：
  ```
  9 类业务  ──一行代码接入──▶  统一审批窗口  ──通过▶ 银行核心清算（完成）
                              （选记录/通过/驳回/留痕）  ──驳回▶ 记录原因、全程留痕
  ```
- **为什么做（一行小字）**：过去每上线一个业务 = 重做一套审批弹窗 → 重复、风格割裂、修一处改 N 处
- **量化表（右侧或底部，数字放大）**：
  | 复用率 **80%** | 接入周期 **1 周 → 0.5 天** | 覆盖 **9 类业务** | 调用方只需 **1 行代码** |
- **视觉**：本页信息密度最高，配色最重；流程图用"业务方 → 引擎 → 核心系统"三段式
- **口播**（60s）：
  > "这是我的核心交付。审批是合规刚需，但审批弹窗本身是重复劳动。我把它收敛成一套公共引擎：9 类业务一行代码接入，通过就进清算、驳回必填原因全程留痕。结果是重复代码降 80%，新业务接入从一周提速到半天。"
