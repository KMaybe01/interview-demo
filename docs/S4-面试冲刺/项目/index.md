> **用途**：回答「你做过什么项目」「这个项目的技术难点在哪」「换到你身上怎么讲」。

>
> ⚠️ **口径说明**：以下 9 篇是**候选人历史项目素材**（多为 Angular / ng-packagr / pnpm 技术栈），描述的是「简历上的项目」，**不是本仓库 `interview-demo` 的实现**。本仓库自身的真实实现见根 [AGENTS.md](https://github.com/KMaybe01/interview-demo/blob/main/AGENTS.md) 与各阶段文档中的代码映射表。讲的时候要说明背景与年代，避免把历史项目的技术栈说成当前仓库选型（当前仓库 JS 侧只用 bun）。

## 2. 推荐顺序（先讲三个最硬的）

1. **动态表单引擎**（Schema AST + 校验 + 注册表）→ 展示「设计能力」
2. **GIS 十万级点位优化** → 展示「性能攻坚能力」
3. **高性能表格 / 权限库** → 展示「组件库与基础建设能力」

其余项目作为「我还能做这些」的补充，不必每个都展开。

## 3. 通用讲法（每篇都套这个五段）

| 段 | 要说清什么 | 常见扣分 |
|----|-----------|----------|
| ① 背景 | 业务场景 + 规模（用户量 / 数据量 / 团队） | 只说「做了一个后台」 |
| ② 我的角色 | 主导 / 参与 / 负责哪一块 | 全程「我们」，说不出自己做了什么 |
| ③ 选型与取舍 | 为什么选 A 不选 B，代价是什么 | 只列技术栈，没有取舍 |
| ④ 难点与解法 | 一个具体坑 + 排查过程 + 最终方案 | 只有结论，没有过程 |
| ⑤ 结果数据 | 前后对比 + 测量口径 | 只给百分比，没有基线 |

> 追问三件套：**为什么这么选？有没有别的方案？换到更大规模还成立吗？** 详见 [00-面试技术亮点汇总](../00-面试技术亮点汇总.md)。
