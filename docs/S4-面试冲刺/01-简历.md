#### 高频场景应答模板

##### 场景一：为什么自研表单引擎而非 @rjsf？

| 对比维度 | @rjsf | 自研方案 | 我的决策依据 |
|----------|-------|----------|-------------|
| 条件显隐 | 仅支持静态 visible | 运行时表达式解析(new Function / CSP降级DSL) | 业务需要动态显隐逻辑 |
| 字段联动 | 需手动编写 effect | autoFill + 依赖图拓扑排序 + 死循环检测 | 7种网元参数间强关联 |
| 实时JSON编辑 | 不支持双向绑定 | forwardRef 暴露 setFormData | 调试时需直接查看/修改 Schema |
| 复杂度 | ~50KB bundle | 4核心文件 + 7字段组件，无外部依赖 | 微内核架构，后续复用成本为零 |

##### 场景二：1000+ QPS 如何保证 60fps？

> "核心矛盾：4000 msg/s → 每秒 setState 4000 次 → reconciliation 来不及 → 丢帧 47%。
>
> 我的解法：`bufferTime(16ms, undefined, 64条)` + `animationFrameScheduler` RAF 双缓冲。
> 效果：4000 msg/s → 每帧合并~64条 → setState 仅 60次/s → 60fps 全帧率。
>
> 配合断线重连(指数退避+jitter)、心跳保活(30s ping/10s pong)、消息去重(Set上限5000)，实现平台可用性 99.9%。"

##### 场景三：十万级 GIS 点位为什么不直接用 WebGL？

> "四重策略是渐进式的——优先利用 Canvas 2D 够用原则：
>
> BBOX视口裁剪(↓60%不可见点) → Cluster聚类聚合(40k→~50点) → dataCache全量缓存(平移/缩放零请求) → moveend惰性刷新(拖动全程60fps)。
>
> 优化结果：Feature数从100k降至~50，内存从~200MB降至~30MB(↓85%)。
>
> 如果未来百万级——10万内Canvas 2D足够，10万~100万切换WebGL(Mapbox GL/Deck.gl)，超100万必须Tile分级加载。四重策略为这种演进留好了扩展边界。"

##### 场景四：Angular Signals vs RxJS 怎么选？

> "我的选型原则：**组件内部用 Signal，跨组件/模块用 RxJS/NgRx，两者共存不排斥。**
>
> Signal 适合 UI 状态（分页/排序/选中行），同步推送、细粒度自动追踪、无需 subscribe/unsubscribe；
> RxJS 保留给事件流（列拖拽广播、HTTP异步数据流、WebSocket连接管理）。
>
> 在实际项目中，@axyom-ui/table 的三态分页、TemplateRef 注册表全部用 Signal 管理；而多协议降级传输层的 WS/SSE/Polling 切换则用 RxJS Observable 管道表达（retry/switchMap/takeUntilDestroyed）。"

#### 详细版（3分钟）

```text
面试官您好，我有近4年前端开发经验，主要技术栈是 React + Angular 双栈 + TypeScript，对企业级ToB平台研发、实时通信系统架构和性能优化有深度实践经验。

我参与并主导了三个核心项目：5G核心网测试用例管理系统、企业级综合网络管理系统(AeMS)、@axyom-ui企业级内部组件库。

我从三个维度来介绍我的技术能力：

━━━ 第一，实时通信与高并发处理 ━━━

在AeMS系统中，我需要处理十万级网元设备的实时监控和1000+QPS告警并发推送。核心挑战在于：企业内网可能屏蔽WebSocket，代理会超时断开，但告警又必须秒级触达。

我的方案是多协议降级传输层：统一Transport接口抽象，设计WebSocket → SSE → HTTP Polling三级降级链路。关键设计包括——

- 指数退避+jitter断线重连，避免重连风暴
- bufferTime(16ms/64条)+animationFrameScheduler RAF双缓冲渲染，4000msg/s→每帧合并~64条→setState仅60次/s→60fps全帧率
- 心跳保活(30s ping/10s pong)检测僵尸连接，消息去重(Set上限5000)防重连后重复
- 二进制协议编码减少payload体积30%+

效果：优化前丢帧47%(18fps)，优化后全帧率60fps，平台可用性99.9%，企业内网兼容性从75%提升至100%。

━━━ 第二，性能优化与大数据渲染 ━━━

我重点攻克了两个性能瓶颈：

1. GIS十万级点位渲染：
   BBOX视口裁剪(↓60%不可见点) → Cluster聚类聚合(distance=40px, 40k→~50点) → dataCache全量缓存(平移缩放零请求) → moveend惰性刷新+RAF节流(拖动全程60fps)。
   结果：Feature数从100k降至~50，帧率<10fps→60fps(7×提升)，内存~200MB→~30MB(↓85%)。

2. LRU路由页面缓存(Angular RouteReuseStrategy)：
   实现shouldDetach/store/shouldAttach/retrieve四阶段生命周期，LRU淘汰+staleKeys写后失效+TTL惰性过期(30s)+滚动位置异步恢复+模块级隔离。
   结果：页面切换性能提升60%，消除模块切换白屏等待。

━━━ 第三，架构设计与工程化 ━━━

1. 递归动态表单引擎(self-built, 非 @rjsf)：
   将Schema抽象为4层AST树(tabs→card→form→leaf)，递归渲染器逐层解析，策略模式注册7种字段组件。支持条件显隐表达式运行时解析、字段联动依赖图拓扑排序+死循环检测、四级校验体系。
   选型依据：@rjsf适合标准JSON Schema场景，但我们的条件显隐+字段联动+实时JSON编辑需求超出了通用库的灵活度。自研方案完全可控，4个核心文件+7个字段组件形成微内核架构，后续复用成本为零。
   结果：开发人效提升80%(3人天→0.5小时)，覆盖7种网元类型200+字段的复杂场景，复用于2个独立项目。

2. RBAC位编码权限体系：
   O(1)位运算权限检查 + 菜单/路由/按钮三层联动 + 后端API双校验。6种权限仅占4字节存储。
   结果：越权漏洞发生率降低90%。

3. @axyom-ui企业级组件库：
   Angular 22 + Signals API(signal/computed/model)替代传统RxJS管理UI状态，最简配置仅cols(rows)两个入参；五层架构+注册表模式+20种组件类型。ng-packagr发布FESM+tree-shaking Library，GitLab CI条件触发(test→build→npm publish)全自动流水线。
   结果：表格业务代码减少80%，表单开发人效提升80%，复用5+内部项目。

━━━ 工程化全链路 ━━━

构建：Vite 8 + Rolldown Rust bundler(首屏↓92%，构建2.38s)；ng-packagr Library + Turborepo monorepo编排
```
