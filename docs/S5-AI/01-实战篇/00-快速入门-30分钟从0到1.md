## 1. 初始化项目

用一个最小 Vite + React 项目（比 Next.js 更快上手、更接近本仓库 `apps/ai-demo` 的形态）。

```bash
# 1) 脚手架（bun 是本仓库统一包管理器）
bunx create-vite@latest ai-app --template react-ts
cd ai-app
bun install

# 2) AI SDK 7 核心 + 一个 Provider（按需选一个）
bun add ai @ai-sdk/react @ai-sdk/openai zod
#    或用 Anthropic / Google：
# bun add @ai-sdk/anthropic   # 或 @ai-sdk/google

# 3) Markdown 渲染（聊天 UI 用）
bun add react-markdown remark-gfm
```

> ⚠️ **版本基线**：`ai` 需 `node >= 22`，`zod` 需 `^3.25.76 || ^4.1.8`。
> 用 `bun add ai` 装到最新 7.x patch 即可；不需要手写版本号。

**验证点**：`bun dev` 起本地服务，浏览器能看到 Vite 默认页 → 继续。

## 2. 服务端：一条流式路由

> 这里我们用 Vite 自带的 dev server 不方便写「API 路由」，所以最小示例把 LLM 调用放在一个 **Node 端模块**里演示。生产环境你把它换成 Next.js API Route / Hono / 任意 BFF 都一样。

先配环境变量：

```bash
# .env（不要提交进 git）
OPENAI_API_KEY=sk-xxxxxxxx
```

服务端流式生成（`lib/ai.ts`）：

```ts
import { openai } from '@ai-sdk/openai';
import { streamText, type LanguageModel, type ModelMessage } from 'ai';

// ① 模型注册表：按「任务档位」而非「厂商」命名
export const models = {
  fast: openai('gpt-5-mini'),        // 日常对话：低成本档
  smart: openai('gpt-5'),           // 复杂任务：旗舰档
} satisfies Record<string, LanguageModel>;

export async function* chatStream(
  messages: ModelMessage[],
  task: keyof typeof models = 'fast',
): AsyncGenerator<string> {
  const result = streamText({
    model: models[task],
    messages,
    system: '你是简洁、专业的 AI 助手。',
    temperature: 0.7,
    maxOutputTokens: 2048,
    // 面向用户一律流式；首字延迟(TTFO)是体验头号指标
  });

  for await (const chunk of result.textStream) yield chunk;
}
```

**关键概念（背下来）**：

- `streamText` = 流式生成引擎，`textStream` 逐 token 吐出。
- 按「**任务难度**」选模型档，而不是一把梭用旗舰——简单意图走 `fast`，命中难例再升 `smart`。
- `temperature` 控随机性（创意调高 / 事实调低）；`maxOutputTokens` 是 v7 新名（旧 `maxTokens`）。

**验证点**（在 `node` 里手动跑，或临时写个 route）：

```ts
const gen = chatStream([{ role: 'user', content: '用一句话解释 SSE' }]);
for await (const c of gen) process.stdout.write(c);   // 应逐字打印
```

## 3. 前端：`useChat` 聊天界面

这是 AI SDK 7 里**改动最大、最容易写错**的一块，务必对照下面的「新 API」。

`src/Chat.tsx`：

```tsx
'use client';
import { useState } from 'react';
import { useChat } from '@ai-sdk/react';
import { DefaultChatTransport } from 'ai';
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';

export default function Chat() {
  const [input, setInput] = useState('');

  // ✅ AI SDK 7：显式 transport；输入/loading 由调用方自己管
  const { messages, sendMessage, status, stop, error, regenerate } = useChat({
    transport: new DefaultChatTransport({ api: '/api/chat' }),
  });

  const busy = status === 'submitted' || status === 'streaming';

  // ✅ 消息正文在 parts 里，不再用 message.content
  const toText = (parts: Array<{ type: string; text?: string }>) =>
    parts.filter((p) => p.type === 'text').map((p) => p.text ?? '').join('');

  return (
    <div className="flex h-screen flex-col">
      <div className="flex-1 overflow-y-auto p-4">
        {messages.map((m) => (
          <div key={m.id} className="mb-3">
            <strong>{m.role === 'user' ? '我' : 'AI'}</strong>
            {m.role === 'assistant' ? (
              <ReactMarkdown remarkPlugins={[remarkGfm]}>{toText(m.parts)}</ReactMarkdown>
            ) : (
              <p className="whitespace-pre-wrap">{toText(m.parts)}</p>
            )}
          </div>
        ))}
        {error && (
          <div className="text-red-600">
            出错了 <button onClick={regenerate}>重试</button>
          </div>
        )}
      </div>

      <form
        className="flex gap-2 border-t p-4"
        onSubmit={(e) => {
          e.preventDefault();
          if (!input.trim() || busy) return;
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="flex-1 border rounded px-3 py-2"
          value={input}
          onChange={(e) => setInput(e.target.value)}
          placeholder="输入消息…"
        />
        {busy ? <button type="button" onClick={stop}>停止</button> : <button type="submit">发送</button>}
      </form>
    </div>
  );
}
```

**AI SDK 7 前端新 API 速记**（面试常考，记牢）：

| 旧写法（v4/v5） | AI SDK 7 写法 |
|---|---|
| `useChat({ api })` | `useChat({ transport: new DefaultChatTransport({ api }) })` |
| `input / handleInputChange / handleSubmit` | 自己 `useState` 管输入，`sendMessage({ text })` 发送 |
| `isLoading` | `status`：`'ready' \| 'submitted' \| 'streaming' \| 'error'` |
| `message.content`（字符串） | `message.parts`（`text`/`tool-call`/`tool-result`/`reasoning`/`source`） |
| `toDataStreamResponse()` | `toUIMessageStreamResponse()` |
| `convertToCoreMessages()` | `convertToModelMessages()` |

**验证点**：把第 2 步的 `chatStream` 挂到你项目里的 `/api/chat` 路由（Next.js / Hono / Vite plugin 均可），浏览器输入「用一句话解释 SSE」→ 看到**逐字打字机渲染** → 核心目标达成 ✅。

> 完整可运行参考：`apps/ai-demo/src/services/aiStream.ts`（本仓库 Go 后端的 SSE 客户端）与
> [01-入门期-AI聊天室](./01-入门期-AI聊天室.md)、[09-AI SDK 数据连接与聊天](./09-AI%20SDK%20数据连接与聊天.md)。

## 4. 模型注册表 + 结构化输出

**换模型**：业务代码只写 `'openai/gpt-5-mini'` 这类字符串或注册表 key，换厂商不改代码（配合 AI Gateway 尤其干净）。

**结构化输出**（v7 用 `Output.*()`，`generateObject` 已废弃）：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, Output } from 'ai';
import { z } from 'zod';

const RecipeSchema = z.object({
  title: z.string(),
  ingredients: z.array(z.object({ name: z.string(), amount: z.string() })),
  steps: z.array(z.string()).min(1),
});

const { output } = await generateText({
  model: openai('gpt-5-mini'),
  output: Output.object({ schema: RecipeSchema }),   // 类型安全的强约束输出
  prompt: '给我一份番茄炒蛋的做法',
});
// output 已通过 Zod 校验，是 z.infer<typeof RecipeSchema>
```

> 流式版用 `experimental_useObject`（`@ai-sdk/react`），前端边生成边渲染**部分对象**——记得对字段做 `?.`。

## 5. 加一个工具 + 停止条件（最小 Agent）

工具调用让模型「动手」。**有工具就必须有停止条件**，否则会无限循环烧钱。

```ts
import { openai } from '@ai-sdk/openai';
import { streamText, tool, stepCountIs, convertToModelMessages, type UIMessage } from 'ai';
import { z } from 'zod';

// description 写给「模型」看：写成触发条件，而非实现机制
const weatherTool = tool({
  description: '当用户询问某个城市当前天气时使用。',
  inputSchema: z.object({ city: z.string() }),
  execute: async ({ city }) => {
    const res = await fetch(
      `https://api.weather.example.com/current?city=${encodeURIComponent(city)}`,
      { signal: AbortSignal.timeout(5000) },
    );
    if (!res.ok) throw new Error(`天气服务返回 ${res.status}`);
    return res.json();
  },
});

// 服务端路由：带工具的流式生成
const result = streamText({
  model: openai('gpt-5-mini'),
  messages: convertToModelMessages(uiMessages),
  tools: { weather: weatherTool },
  stopWhen: stepCountIs(5),      // 🛑 最多 5 步（默认安全上限 20）
});
return result.toUIMessageStreamResponse();
```

前端渲染时**不能只画 `text`**——把 `tool-call` / `tool-result` 也画出来，用户才看得见模型「做了什么」：

```tsx
{m.parts.map((part, i) => {
  if (part.type === 'text') return <p key={i}>{part.text}</p>;
  if (part.type === 'tool-call')
    return <div key={i}>正在调用 <code>{part.toolName}</code>…</div>;
  if (part.type === 'tool-result')
    return <pre key={i}>{JSON.stringify(part.output)}</pre>;
  return null;
})}
```

> 想升级为**带审批、超时、持久化**的 Agent → 直接看 [09-AI SDK 数据连接与聊天](./09-AI%20SDK%20数据连接与聊天.md) 的 `ToolLoopAgent` 小节。

## 6. 可观测 + 自检清单

一次注册，全局生效：

```ts
// instrumentation.ts
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';   // bun add @ai-sdk/otel
registerTelemetry(new OpenTelemetry());
```

**上线前 5 指标**（最小可观测）：TTFO、输出 tokens/s、单会话总成本、工具失败率、`finishReason` 分布。

**自检清单**：

- [ ] 每个带 `tools` 的调用都设了 `stopWhen`
- [ ] 用户侧调用设了 `timeout`（至少 `totalMs` + `chunkMs`）
- [ ] 前端渲染覆盖了 5 种 part，不只是 `text`
- [ ] 高风险工具配了审批（`toolApproval`）
- [ ] `messages` 有裁剪（滑动窗口 / 摘要），不会无限增长
- [ ] 密钥只在服务端，第三方工具用 `contextSchema` 隔离

## 高频踩坑（AI SDK 7）

| 症状 | 原因 | 修复 |
|---|---|---|
| `useChat` 拿不到 `input` / `isLoading` | 用了旧版 API | `useState` 管输入，用 `status` |
| 打印 `message.content` 是 `undefined` | v5+ 正文在 `parts` | 遍历 `message.parts` |
| 调了工具但界面没反应 | 只渲染了 `text` part | 补 `tool-call` / `tool-result` 分支 |
| Agent 停不下来 / 账单暴涨 | 没设停止条件 | `stopWhen: stepCountIs(N)` + 上下文裁剪 |
| `generateObject` 告警 | 已废弃 | `generateText` + `output: Output.object({ schema })` |
| 流式一个字一个字抖 | 没做平滑分块 | `experimental_transform: smoothStream({ chunking })` |
