## 三、技术选型答辩句式

### 为什么选 A 而不是 B？

**模板**：

> "我们选了 **A** 而非 **B**，主要基于三个考量：
> 1. **业务上**：（场景需要...）
> 2. **工程上**：（团队技术栈/交付周期...）
> 3. **成本上**：（A 的成本优势...）"

### 常见技术选型问答

#### Q: 为什么选 AI SDK 而不是 LangChain？

> "我们选了 **AI SDK** 而非 **LangChain**，主要基于三个考量：
> 1. **业务上**：项目是前端主导的 Agent 应用，AI SDK 对 React/Vue 的支持最好，有完善的 Hooks
> 2. **工程上**：我们团队是 TypeScript 全栈，AI SDK 类型安全，LangChain 的 Python 风格在 JS 生态兼容性差
> 3. **成本上**：AI SDK 学习成本低，不需要额外抽象层，开发效率更高"

#### Q: 为什么用 MCP 而不是 Function Calling？

> "我们选了 **MCP** 而非原生 **Function Calling**，主要基于三个考量：
> 1. **业务上**：项目需要接入 5+ 工具，MCP 的标准化接口让工具可复用
> 2. **架构上**：MCP 支持动态发现，Agent 运行时自动获取工具列表，不需要硬编码
> 3. **扩展上**：社区 MCP Server 生态丰富，后续接入新工具成本很低"

#### Q: 为什么用 DeepSeek 而不是 GPT-4？

> "我们选了 **DeepSeek** 而非 **GPT-4**，主要基于三个考量：
> 1. **合规上**：项目面向国内市场，DeepSeek 数据不出境
> 2. **成本上**：DeepSeek R1 的推理成本是 GPT-4o 的 1/10
> 3. **性能上**：在代码生成任务上，DeepSeek R1 表现接近 o1"

## 四、常见追问应对策略

### 追问1: 为什么不用 ChatGPT/Claude 直接做？

**回答要点**：

> "我们评估过直接用 ChatGPT，最终选择自建，主要考虑：
> 1. **数据安全**：企业知识库不能上传到外部 API
> 2. **定制化**：需要针对业务场景优化 Prompt 和工具链
> 3. **成本可控**：高并发场景下自建更经济
> 4. **功能扩展**：需要与内部系统（工单/CRM）深度集成"

### 追问2: 为什么不用 LangChain？

**回答要点**：

> "LangChain 功能全面，但我们最终选择手搓，原因：
> 1. **抽象层重**：LangChain 的抽象增加了调试难度
> 2. **版本不兼容**：LangChain v0.3 和 v0.2 有大量 breaking changes
> 3. **场景匹配**：我们的 Agent 需求相对标准，AI SDK 已足够
> 4. **团队技术栈**：TypeScript 全栈，AI SDK 的 React 集成更自然"

### 追问3: 项目中最大的失败是什么？

**回答要点**（坦诚 + 复盘）：

> "最大的失败是**前期没有做工具分层预判**，导致 Agent 经常误调用重工具。
>
> 比如用户问'你好'，Agent 会触发知识库检索，浪费 2-3 秒。
>
> **改进方案**：增加了意图识别层，对问题做预判，将准确率从 78% 提升到 94%。
>
> **学到的教训**：Agent 设计中，'什么时候不用工具'比'怎么用工具'更重要。"

### 追问4: 如果重新做，你会改进什么？

**回答要点**（展示复盘能力）：

> "如果重新做，我会改进三点：
> 1. **早期引入评估体系**：而不是手动测试，用 LLM-as-Judge 自动评估
> 2. **更细粒度的工具拆分**：把大工具拆成小工具，提高复用性
> 3. **更完善的监控**：从一开始就建立 Trace 系统，而不是事后补充"

## 五、高频技术问题速答

### Q: Agent 和 Chain 的区别？

> **Chain**：线性流水步，每个步骤确定，适合简单流程
>
> **Agent**：LLM 驱动的自主决策，根据中间结果动态选择下一步
>
> **类比**：Chain 是流水线工人，Agent 是有自主判断的工程师

### Q: MCP 是什么？解决了什么问题？

> **MCP**：Model Context Protocol，Anthropic 提出的工具接入协议
>
> **解决的问题**：工具标准化接入。类似 USB-C 统一了设备接口，MCP 统一了 LLM 与工具的通信方式
>
> **核心价值**：一次开发，多处复用；动态发现；生态共享

### Q: RAG 的核心流程？

> **四步**：
> 1. **索引**：文档分块 → Embedding → 存入向量库
> 2. **检索**：Query → 向量检索 + 重排序
> 3. **增强**：检索结果 + 原始问题 → 组装 Prompt
> 4. **生成**：LLM 生成答案

### Q: 如何评估 Agent 的质量？

> **三个维度**：
> 1. **任务完成率**：端到端成功率
> 2. **效率指标**：步骤数、耗时、工具调用次数
> 3. **安全指标**：越权操作次数、Prompt 注入成功率
>
> **评估方法**：LLM-as-Judge + 人工抽检 + 回归测试

## 六、面试节奏把控

### 时间分配建议

| 环节 | 时间 | 要点 |
|------|------|------|
| 自我介绍 | 1-2 分钟 | 突出 AI 方向 + 量化成果 |
| 项目经历 | 5-8 分钟 | STAR 法则 + 技术细节 |
| 技术问答 | 15-20 分钟 | 精准回答 + 适当扩展 |
| 反问环节 | 3-5 分钟 | 问业务/团队/技术栈 |

### 反问技巧

**推荐问题**：

1. "团队目前的 Agent 项目处于什么阶段？"（了解业务）
2. "技术栈主要用什么？AI SDK 还是 LangChain？"（了解技术选型）
3. "Agent 的评估体系是怎么做的？"（展示专业度）

**避免问题**：

- "你们加班多吗？"（显得不专业）
- "工资多少？"（面试中不合适）
- "用什么语言？"（应该提前了解）
