## 一、Function Calling

### Q1: Function Calling 的原理？

> **一句话**：LLM 根据用户意图，自动选择并调用预定义的函数，返回结构化结果。
>
> **工作流程**：
> 1. 开发者定义工具（函数名、参数、描述）
> 2. 用户输入问题
> 3. LLM 分析意图，决定调用哪个工具
> 4. 返回工具名 + 参数（JSON 格式）
> 5. 开发者执行函数，将结果返回给 LLM
> 6. LLM 基于结果生成最终回复
>
> **关键**：LLM 只生成调用指令，不执行代码。

### Q2: Function Calling 和 MCP 的区别？

> | 维度 | Function Calling | MCP |
> |------|------------------|-----|
> | **定义方** | 各厂商各自实现 | Anthropic 开放标准 |
> | **工具描述** | JSON Schema | 工具自描述 |
> | **发现机制** | 静态定义 | 动态发现 |
> | **生态** | 厂商锁定 | 社区共享 |
> | **适用场景** | 简单工具调用 | 复杂工具生态 |
>
> **类比**：Function Calling 是专有接口，MCP 是 USB-C 标准接口。

### Q3: 如何设计好的工具描述？

> **四大原则**：
> 1. **清晰明确**：让 LLM 理解何时使用
> 2. **参数完整**：所有参数都有描述和类型
> 3. **返回格式**：明确返回结构
> 4. **示例**：提供调用示例
>
> **示例**：
> ```json
> {
>   "name": "search_knowledge",
>   "description": "搜索知识库，返回相关文档片段。当用户询问事实性问题时使用。",
>   "parameters": {
>     "query": {
>       "type": "string",
>       "description": "搜索关键词"
>     }
>   }
> }
> ```

## 二、MCP 协议

### Q4: MCP 是什么？解决了什么问题？

> **一句话**：Model Context Protocol，Anthropic 提出的工具接入标准协议。
>
> **解决的问题**：工具标准化接入。类似 USB-C 统一了设备接口，MCP 统一了 LLM 与工具的通信方式。
>
> **核心价值**：
> 1. **一次开发，多处复用**：MCP Server 可在 Claude Desktop、Cursor 等多个宿主使用
> 2. **动态发现**：Agent 运行时自动发现可用工具
> 3. **生态繁荣**：社区共建工具市场，降低开发门槛

### Q5: MCP 的三大核心能力？

> **三大能力**：
> 1. **Tools（工具）**：可执行的操作（搜索、写文件）
> 2. **Resources（资源）**：可读取的数据（文件、数据库）
> 3. **Prompts（提示模板）**：预定义的 Prompt 模板
>
> **架构**：
> ```
> MCP Host（Claude Desktop）
>     ↓
> MCP Client（协议客户端）
>     ↓
> MCP Server（工具提供方）
>     ↓
> 外部资源（API、数据库、文件）
> ```

### Q6: MCP 的通信方式有哪些？

> **两种传输方式**：
> 1. **stdio**：标准输入输出，适合本地工具
> 2. **Streamable HTTP**：HTTP 长连接，适合远程服务（2025 新增）
>
> **选择依据**：
> - 本地工具 → stdio
> - 远程服务 → Streamable HTTP
> - 需要实时推送 → SSE
>
> **注意**：Streamable HTTP 正在取代纯 SSE 方式。

### Q7: 如何开发一个 MCP Server？

> **开发步骤**：
> 1. 选择语言（TypeScript/Python）
> 2. 使用官方 SDK（@modelcontextprotocol/sdk）
> 3. 定义工具（name、description、parameters）
> 4. 实现工具逻辑
> 5. 注册到 MCP Host
>
> **示例代码**：
> ```typescript
> import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
>
> const server = new McpServer({ name: 'my-server', version: '1.0.0' });
>
> server.tool('search', { query: z.string() }, async ({ query }) => {
>   // 实现搜索逻辑
>   return { content: [{ type: 'text', text: results }] };
> });
> ```

## 三、A2A 协议

### Q8: A2A 是什么？

> **一句话**：Agent-to-Agent Protocol，Google 主导的 Agent 间通信协议。
>
> **解决的问题**：不同厂商、不同框架的 Agent 能互相协作。
>
> **核心能力**：
> 1. **Agent 发现**：通过 Agent Card 描述能力
> 2. **任务协作**：定义任务生命周期
> 3. **消息交换**：结构化消息格式
>
> **与 MCP 的关系**：
> - MCP：Agent 与工具的通信
> - A2A：Agent 与 Agent 的通信

### Q9: A2A 和 MCP 的区别？

> | 维度 | MCP | A2A |
> |------|-----|-----|
> | **通信对象** | Agent ↔ 工具 | Agent ↔ Agent |
> | **发起方** | Anthropic | Google |
> | **核心能力** | 工具调用 | 任务协作 |
> | **生态** | 工具市场 | Agent 市场 |
>
> **类比**：
> - MCP 是 USB-C（设备接口）
> - A2A 是 HTTP（服务间通信）
>
> **互补关系**：MCP 让 Agent 能用工具，A2A 让 Agent 能协作。

### Q10: A2A 的核心概念？

> **三大概念**：
> 1. **Agent Card**：描述 Agent 能力的元数据（类似 API 文档）
> 2. **Task**：Agent 间协作的任务单元
> 3. **Message**：任务过程中的消息交换
>
> **工作流程**：
> ```
> Agent A 发现 Agent B（通过 Agent Card）
>     ↓
> Agent A 创建 Task 发送给 Agent B
>     ↓
> Agent B 执行任务，返回结果
>     ↓
> Agent A 继续后续处理
> ```

## 四、通信协议

### Q11: SSE 和 WebSocket 的区别？

> | 维度 | SSE | WebSocket |
> |------|-----|-----------|
> | **方向** | 服务端 → 客户端（单向） | 双向 |
> | **协议** | HTTP | 独立协议 |
> | **复杂度** | 低 | 高 |
> | **适合场景** | 流式输出、实时推送 | 实时聊天、游戏 |
>
> **AI 场景**：
> - LLM 流式输出 → SSE
> - 实时聊天 → WebSocket

### Q12: AI Gateway 的核心功能？

> **六大功能**：
> 1. **统一接口**：所有模型用同一个 API 格式
> 2. **智能路由**：根据场景选择最优模型
> 3. **Fallback**：主模型失败自动切换备用
> 4. **限流**：控制 QPS、Token 用量
> 5. **缓存**：相同请求返回缓存
> 6. **监控**：延迟、成本、错误率追踪
>
> **推荐工具**：LiteLLM（开源自建）、One API（国产友好）、Portkey（托管）。

## 五、面试速答

### Q13: 你了解哪些 MCP Server？

> **常用 Server**：
> - **Playwright**：浏览器自动化
> - **GitHub**：代码管理
> - **PostgreSQL**：数据库查询
> - **Brave Search**：网络搜索
> - **Filesystem**：文件操作
>
> **推荐组合**：Playwright + GitHub + PostgreSQL + Brave Search。

### Q14: MCP 的动态发现是什么意思？

> **一句话**：Agent 运行时自动获取可用工具列表，不需要硬编码。
>
> **实现原理**：
> 1. MCP Host 启动时连接所有 MCP Server
> 2. 调用 `tools/list` 获取工具列表
> 3. 工具描述注入到 LLM 的 System Prompt
> 4. LLM 根据描述决定使用哪个工具
>
> **优势**：热插拔、易扩展、解耦。
