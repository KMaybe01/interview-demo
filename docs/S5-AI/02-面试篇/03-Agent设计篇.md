# Agent 设计篇（面试精简版）

> Agent 相关面试题，聚焦架构设计和工程实践。

## 一、Agent 核心概念

### Q1: 什么是 Agent？与 LLM 有什么区别？

> **一句话**：Agent = LLM（大脑）+ Tools（手脚）+ Memory（记忆）+ Planning（规划）
>
> | 维度 | LLM | Agent |
> |------|-----|-------|
> | 输出 | 文本 Token | 可执行动作 |
> | 记忆 | 上下文窗口 | 长期+短期记忆 |
> | 工具 | 无 | Function Calling/MCP |
> | 循环 | 单次推理 | ReAct 循环 |
> | 自主性 | 被动响应 | 主动规划 |
>
> **核心区别**：LLM 只能生成文本，Agent 能自主决策并执行操作。

### Q2: Agent 的核心组件？

> **四大组件**：
> 1. **大脑（LLM）**：理解、推理、决策
> 2. **工具（Tools）**：执行操作（搜索、API、数据库）
> 3. **记忆（Memory）**：短期（上下文）+ 长期（向量库）
> 4. **规划（Planning）**：任务分解、策略选择
>
> **工作流程**：感知 → 推理 → 规划 → 执行 → 反思 → 循环

### Q3: Agent 和 Chain 的区别？

> **Chain**：线性流水步，步骤固定，适合简单流程
>
> **Agent**：LLM 驱动的自主决策，根据中间结果动态选择下一步
>
> **类比**：
> - Chain 是流水线工人，按固定流程操作
> - Agent 是有自主判断的工程师，根据情况调整策略
>
> **选择依据**：流程固定用 Chain，需要自主决策用 Agent。

## 二、Agent 设计模式

### Q4: ReAct 是什么？

> **一句话**：Reasoning + Acting 的结合，交替进行思考和行动。
>
> **工作流程**：
> ```
> 思考：用户要查天气，需要调用天气工具
> 行动：调用 get_weather("北京")
> 观察：返回"晴，25°C"
> 思考：天气信息已获取，可以生成回复
> 输出：北京今天晴，25°C
> ```
>
> **优势**：推理过程透明、可解释
>
> **劣势**：循环次数需要限制，否则可能死循环
>
> **框架支持**：LangGraph、Vercel AI SDK 都支持。

### Q5: Plan-and-Execute 是什么？

> **一句话**：先规划完整步骤，再逐步执行，适合复杂任务。
>
> **与 ReAct 对比**：
> | 维度 | ReAct | Plan-and-Execute |
> |------|-------|------------------|
> | **决策方式** | 边做边想 | 先想后做 |
> | **适用场景** | 简单任务 | 复杂多步任务 |
> | **效率** | 每步都调 LLM | 规划一次，执行多次 |
> | **灵活性** | 高 | 中（规划后难调整） |
>
> **推荐**：简单任务用 ReAct，复杂任务用 Plan-and-Execute。

### Q6: Multi-Agent 协作模式有哪些？

> **三种主要模式**：
> 1. **协作模式**：多个 Agent 分工合作，共同完成任务
> 2. **辩论模式**：多个 Agent 辩论，得出更准确结论
> 3. **监督模式**：一个 Agent 监督其他 Agent，确保质量
>
> **设计要点**：
> - 明确每个 Agent 的职责边界
> - 设计清晰的通信协议
> - 避免循环调用
> - 有明确的终止条件

## 三、Agent 工程实践

### Q7: 如何防止 Agent 无限循环？

> **四种防护策略**：
> 1. **最大迭代次数**：设置上限（如 10 次）
> 2. **超时机制**：单次循环 30 秒，整体 5 分钟
> 3. **重复检测**：相同工具+参数连续出现 3 次则停止
> 4. **成本控制**：Token 消耗超过阈值则停止
>
> **实现代码**（AI SDK）：
> ```ts
> const result = await generateText({
>   maxSteps: 10,        // 最大迭代次数
>   abortSignal: AbortSignal.timeout(30000),
> });
> ```
>
> **经验**：生产环境必须有防护，否则一个失控循环可能烧掉大量 Token。

### Q8: Agent 工具设计原则？

> **五大原则**：
> 1. **单一职责**：一个工具只做一件事
> 2. **明确描述**：工具描述要清晰，让 LLM 理解何时使用
> 3. **参数简单**：参数尽量少，类型要明确
> 4. **幂等性**：相同输入相同输出，允许重试
> 5. **错误处理**：返回明确错误信息，不要静默失败
>
> **示例**：
> ```ts
> const searchTool = tool({
>   description: '搜索知识库，返回相关文档片段',
>   parameters: z.object({
>     query: z.string().describe('搜索关键词'),
>   }),
>   execute: async ({ query }) => {
>     // 实现
>   },
> });
> ```

### Q9: Agent 安全防护怎么做？

> **三层防护**：
>
> **输入层**：
> - Prompt 注入检测
> - 敏感词过滤
> - 输入长度限制
>
> **执行层**：
> - 工具权限控制（读/写/执行）
> - 人工确认机制（高风险操作）
> - 沙箱环境执行
>
> **输出层**：
> - 输出格式验证
> - 敏感信息过滤
> - 幻觉检测
>
> **关键原则**：最小权限原则，Agent 只能访问必要的工具和数据。

## 四、Agent 评估与优化

### Q10: 如何评估 Agent 质量？

> **三个维度**：
> 1. **任务完成率**：端到端成功率（最重要）
> 2. **效率指标**：步骤数、耗时、工具调用次数
> 3. **安全指标**：越权操作次数、Prompt 注入成功率
>
> **评估方法**：
> - **LLM-as-Judge**：用 GPT-4 评估输出质量
> - **人工评估**：黄金标准，但成本高
> - **回归测试**：建立测试集，持续监控
> - **A/B 测试**：对比不同版本效果
>
> **工具**：LangSmith、Phoenix、Braintrust。

### Q11: Agent 优化方向有哪些？

> **四大方向**：
> 1. **Prompt 优化**：更清晰的指令、更好的示例
> 2. **工具优化**：更精准的工具描述、更好的错误处理
> 3. **规划优化**：更好的任务分解、更智能的策略选择
> 4. **记忆优化**：更高效的上下文管理、更好的长期记忆
>
> **优先级**：Prompt 优化 > 工具优化 > 规划优化 > 记忆优化
>
> **经验**：80% 的问题可以通过优化 Prompt 解决。

## 五、面试速答

### Q12: 你用过哪些 Agent 框架？

> | 框架 | 特点 | 适合场景 |
> |------|------|---------|
> | **AI SDK** | React 集成好 | 前端主导的 Agent |
> | **LangGraph** | 状态机、可视化 | 复杂工作流 |
> | **CrewAI** | 角色协作 | Multi-Agent |
> | **AutoGen** | 微软、对话式 | 研究探索 |
>
> **推荐**：前端用 AI SDK，复杂编排用 LangGraph。

### Q13: Agent 的可观测性怎么做？

> **三个层面**：
> 1. **Trace**：完整调用链追踪
> 2. **Metrics**：延迟、成功率、成本
> 3. **Logging**：输入输出日志
>
> **工具**：LangSmith（最全）、Helicone（成本分析）、自建方案。
>
> **关键指标**：任务完成率、平均步骤数、Token 消耗、延迟分布。
