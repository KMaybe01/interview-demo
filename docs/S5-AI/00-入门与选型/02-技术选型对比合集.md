## 二、AI 架构模式选型

### 模式特征矩阵

| 模式 | 结构 | 确定性 | 适用场景 | 复杂度 |
|------|------|--------|---------|:------:|
| **Prompt** | 单次调用 | 高 | 简单问答、翻译 | ⭐ |
| **Chain** | 线性 DAG | 中高 | 固定流程（如 RAG） | ⭐⭐ |
| **Router** | 分支选择 | 中 | 意图识别、多路分发 | ⭐⭐⭐ |
| **Agent** | 循环+工具 | 低 | 开放任务、多步推理 | ⭐⭐⭐⭐ |
| **Workflow** | 状态机+并行 | 中高 | 复杂业务流、多人协作 | ⭐⭐⭐⭐⭐ |

### 决策树

```
任务类型？
├─ 简单固定流程 → Chain
├─ 需要外部数据/操作？
│   ├─ 不需要多步推理 → Router + 单步工具
│   └─ 需要多步推理 → Agent (ReAct)
└─ 高可靠性要求 → Workflow (LangGraph)
```

**经验**：80% 用 Chain，慎用 Agent，复杂流用 Workflow。

## 三、AI 模型选型

### 主流模型对比（2026 基线）

> 版本基线以 [../index.md](../index.md#版本基线唯一真源) 为准。模型迭代极快，下表为**档位划分**而非永久结论，
> 落地前请用当前实际模型名替换。

| 档位 | 代表模型（2026-09） | 优势领域 | 相对成本 | 推荐场景 |
|------|-------------------|---------|---------|---------|
| **旗舰推理** | GPT-5 / Claude Opus 5.5 | 复杂 Agent、长程任务、代码 | 高 | 高难度推理、自主 Agent 主模型 |
| **超大上下文** | Gemini 3 系 | 百万级上下文、多模态 | 中高 | 海量文档、音视频理解 |
| **高并发/低成本** | GPT-5-mini / Claude Haiku 系 / Gemini Flash | 速度、成本 | 低 | 分类、意图识别、简单问答 |
| **中文性价比** | DeepSeek V4 / Qwen3 / GLM | 中文、数学、代码 | 低 | 中文客服、逻辑推理、国产化合规 |
| **私有化** | Qwen3 / Llama 系开源权重 | 数据不出域 | 自建成本 | 数据敏感场景、垂直微调 |

> 2026 年的现实：**旗舰模型价格一年内下降一个量级**。选型时优先按「任务难度路由」而非「全局一个模型」——
> 简单意图用低成本档，命中难例再升级到旗舰档。

### 选型决策

```
数据敏感？ ─是→ 私有部署（Qwen / Llama 开源权重 + vLLM / Ollama）
      │
      否
      ↓
需要多模态？ ─是→ Gemini 3 / GPT-5 系
      │
      否
      ↓
任务复杂度？ ─高（多步推理/工具编排）→ 旗舰档（GPT-5 / Claude Opus 5.5）
      │
      低
      ↓
低成本档（GPT-5-mini / Haiku / Gemini Flash / DeepSeek V4 / Qwen3）
```

## 四、框架选型

### 主流框架对比

| 框架 | 语言 | 核心定位 | 优势 | 劣势 | 适用场景 |
|------|------|---------|------|------|---------|
| **AI SDK** | TS | 前端流式 UI | React 集成好 | RAG/Agent 弱 | 聊天界面 |
| **LangChain** | JS/Py | 全链路编排 | 生态大 | 抽象重 | 复杂 RAG/Agent |
| **LlamaIndex** | TS/Py | 数据检索 | RAG 专精 | 通用编排弱 | 企业知识库 |
| **LangGraph** | TS/Py | 状态机工作流 | 循环支持好 | 学习曲线陡 | 复杂 Agent |
| **MCP**（规范 `2026-07-28`） | TS/Py/Go | 工具与资源标准化协议 | 一次开发多处复用、无状态易扩展 | 版本升级有破坏性，需版本协商 | 工具集成、跨应用复用 |

### 选型决策

```
项目类型？
├─ 纯前端聊天 → AI SDK
├─ 复杂 RAG/Agent？
│   ├─ 需要循环/状态 → LangGraph
│   ├─ 侧重数据检索 → LlamaIndex
│   └─ 通用编排 → LangChain
└─ IDE/工具集成 → MCP
```

### 最佳组合

- **黄金搭档**：AI SDK（前端）+ LangChain（后端 RAG）
- **进阶组合**：Next.js + LangGraph（复杂 Agent）+ Pinecone
- **轻量方案**：Hono + AI SDK + Redis

## 五、向量数据库选型

### 主流向量库对比

| 数据库 | 类型 | 优势 | 劣势 | 适用场景 |
|--------|------|------|------|---------|
| **Pinecone** | 托管 SaaS | 开箱即用 | 闭源、贵 | 快速原型 |
| **Milvus** | 开源/托管 | 分布式、高性能 | 部署复杂 | 企业级大规模 |
| **Qdrant** | 开源/托管 | Rust、快 | 社区小 | 高并发 |
| **Chroma** | 开源/嵌入式 | 轻量、简单 | 分布式弱 | 本地开发 |
| **pgvector** | PG 插件 | 关系+向量混合 | 大规模性能瓶颈 | 已有 PG 架构 |

### 选型决策

```
数据规模？
├─ < 100 万 → Chroma / pgvector
└─ > 100 万 → Milvus / Qdrant
    ├─ 不想运维 → Pinecone
    └─ 自建 → Milvus
```

## 七、部署平台选型

### 主流平台对比

| 平台 | 类型 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|---------|
| **Vercel** | Serverless | 零配置、全球 CDN | 函数超时限制 | 前端优先、MVP |
| **Railway** | PaaS | 支持 Docker、长时运行 | 价格略高 | 后台任务 |
| **Render** | PaaS | 免费层级友好 | 冷启动长 | 个人项目 |
| **AWS** | IaaS | 极致弹性、企业级 | 配置复杂 | 大规模生产 |
| **Cloudflare** | Edge | 极低延迟、便宜 | 内存限制 | 轻量 API |

### 部署架构

```
用户 → CDN → 前端静态资源
         → API 路由 (Serverless)
           → LLM API
           → 数据库/向量库
           → Redis 缓存
```

## 十、常见反模式

### 架构设计

- ❌ 把所有逻辑塞进前端 → ✅ 使用 API Routes 代理
- ❌ 盲目追求 Agent → ✅ 优先 Chain，仅在必要时 Agent
- ❌ 忽视上下文限制 → ✅ 滑动窗口/摘要压缩

### 提示词工程

- ❌ 模糊指令 → ✅ 具体任务+格式要求
- ❌ 缺乏约束 → ✅ 明确输出格式
- ❌ 过度依赖 Few-Shot → ✅ 1-3 个示例

### 性能体验

- ❌ 阻塞式 UI → ✅ 流式响应+骨架屏
- ❌ 无错误重试 → ✅ 指数退避重试
- ❌ 忽视移动端 → ✅ 响应式设计
