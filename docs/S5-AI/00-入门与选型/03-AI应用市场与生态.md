## 一、MCP 工具生态

MCP（Model Context Protocol）是 Anthropic 提出的标准化协议，让 Agent 能"插拔式"接入各种工具。

> **当前规范：`2026-07-28`**（上一稳定版 `2025-11-25`）。新版已转向**无状态请求**，
> 并引入 `server/discover`、MRTR、Tasks、MCP Apps 等能力，详见
> [../../01-实战篇/06-前沿技术与生态.md](../01-实战篇/06-前沿技术与生态.md)。

### 1. 浏览器自动化

## 五、Agent 框架与运行时（2026 新增）

> 2026 年的 Agent 开发已不再「直接调 LLM API 手写循环」，而是落在**框架 + 运行时**上。
> 这是前端转型者最容易被面试追问、也最容易缺失的一层。

| 框架 / 运行时 | 语言 | 定位 | 典型场景 |
|--------|------|------|---------|
| **AI SDK 7**（`ToolLoopAgent`、`stopWhen`、审批） | TS | 前端优先的 Agent 循环 + 流式 UI | React 应用内嵌 Agent |
| **Mastra** | TS | 类型安全的 Agent 框架（工作流 / RAG / 评测一体） | TS 全栈 Agent 服务 |
| **LangGraph** | TS/Py | 状态机 + 检查点（Checkpoint）编排 | 复杂多步、可恢复流程 |
| **OpenAI Agents SDK** | Py/TS | 轻量 Agent + Handoff/Guardrails | OpenAI 生态内多 Agent 协作 |
| **Google ADK** | Py/Java | 与 Gemini / Vertex 深度集成 | GCP 上的 Agent 服务 |
| **Claude Agent SDK** | TS/Py | 以 Claude 为主模型的 Agent 运行时 | Agentic Coding、长程任务 |
| **Pydantic AI** | Py | 类型驱动、结构化输出强约束 | 需要严格 schema 的后端 Agent |

**与 MCP / A2A 的关系**：框架解决「单个 Agent 怎么跑」，MCP 解决「工具怎么接」，A2A 解决「Agent 之间怎么协作」。

## 七、面试高频考点

### Q: 你了解哪些 AI 工具和平台？

**参考回答**：

> 我关注四个层面：
> 1. **模型服务**：OpenAI / Anthropic / Google 的旗舰档，配 DeepSeek、Qwen 做成本与合规平衡
> 2. **开发框架**：AI SDK 7（前端流式与 Agent 循环）、LangChain / LangGraph（复杂编排）
> 3. **Agent 框架与运行时**：Mastra、OpenAI Agents SDK、Google ADK、Claude Agent SDK——按语言与部署形态选
> 4. **应用平台**：Dify（企业级）、FastGPT（知识库）
>
> 工具层面，日常使用 Cursor + Claude Code 组合，MCP 协议关注 Playwright 和 GitHub 两个 Server。

### Q: MCP 协议解决了什么问题？

**参考回答**：

> MCP 解决了"工具标准化接入"问题。类似 USB-C 统一了设备接口，MCP 统一了 LLM 与工具的通信方式。
>
> 核心价值：
> 1. **一次开发，多处复用**：MCP Server 可在多个宿主（IDE、桌面端、自研应用）中使用
> 2. **动态发现**：`server/discover` 让客户端在运行前获知服务器支持的协议版本、能力与扩展
> 3. **生态繁荣**：社区共建工具市场，降低开发门槛
>
> 2026-07-28 之后还需要注意两点：协议从**有状态会话**转向**无状态自包含请求**（移除 `initialize` 与
> `Mcp-Session-Id`，远程部署不再依赖粘性会话）；交互界面（MCP Apps）与长任务（Tasks）被拆到**正式扩展**中，
> 需要双方显式协商才能使用。
