# S5-AI 写作约定

> 这份文档是给**继续写教程的人**（包括未来的自己 / AI 助手）看的。
> 目的：任何一篇新章节，读者都能用**同一套心智模型**消费它。

---

## 1. 目录与命名

| 目录 | 放什么 | 命名规则 |
|---|---|---|
| `00`-`06` 关卡目录 | 教程正文（`NN-主题.md`）与原文手册（`附-主题.md`） | `NN-` 两位序号按学习顺序；`附-` 前缀表示**保留原文**的归档手册 |
| `07-Go后端参考实现/` | Go 副线 | 沿用阶段式命名 |
| `08-资料库/` | 大部头原始笔记，**不要求通读** | 只做归档，不再改写内容 |
| `09-面试篇/` | 面试专题与技巧 | `NN-主题篇.md` |
| 根目录 `index.md` | **唯一入口 + 版本基线真源** | 各章节只能引用，不自创版本号 |

`NN-主题.md` 的前两位数字就是阅读顺序，允许空缺（为后续章节预留）。

---

## 2. 章节模板

每一篇正文（`NN-*`）请按下面五段式组织：

```md
# 标题

> **一句话**：本章解决什么问题 / 读者拿走什么能力
>
> **前置**：需要哪一关的知识
> **产出**：跑完本章手上多了什么
> **代码**：`apps/ai-course/0N-xxx/`（或本仓库对应路径）

## 1. 原理（够用即可）
   一张图 + 一段类比。不要展开数学推导。

## 2. 企业实现要点
   业界做法 / 常见坑 / 决策依据。必须有取舍对比表。

## 3. 代码实现
   可直接跑的最小实现；关键行加注释说明"为什么这样写"。

## 4. 验证与观测
   怎么证明它真的 work：curl 命令 / 断言 / 面板指标。

## 5. 面试追问
   3-5 道题，每题给**答题骨架**（观点 + 取舍 + 追问点），不要给背诵式答案。

## 6. 延伸阅读
   指向 08-资料库 或 Go 副线对应章节。
```

不是每篇都必须写满六段，但**「原理」「实现」「追问」三段不可省**。

---

## 3. 版本纪律

1. **版本号只在 [index.md](./index.md) 的基线表定义**，正文用「见版本基线真源」链接引用，不自创版本。
2. 模型型号要写清是**档位**（如"旗舰档"）还是**实例 ID**（如 `gpt-5-mini`），并提醒读者核对当期实列型号。
3. 写协议时必须写清**规范版本**（MCP `2026-07-28`、A2A `v1.0`），禁止把 MCP 描述成有状态协议。
4. 历史代际（GPT-4o 等 2024 世代）只能在"演进脉络"里出现。

---

## 4. 代码纪律

- 本仓库**只用 `bun`**，示例命令不得出现 `npm` / `yarn` / `pnpm`。
- 示例代码优先指向**仓库内真实可跑的路径**，而不是凭空构造的项目。
- 涉及密钥的代码一律读环境变量，禁止硬编码，并提示 `.env` 不入库。
- 迁移/新建文档后必须跑 `bun run docs:check`，保证内部链接 0 死链。

---

## 5. 修改存量的规则

1. **已迁移的存量文档（`附-*` 与 `08-资料库/`）保留正文**，只允许修改：标题层级、失效链接、明显的版本错误。
2. 需要大幅重写时：**新建一篇 `NN-*`**，把旧文降级为「附-」归档，而不是就地推翻。
3. 删除文档前先确认：这篇内容是否已在别处被覆盖？若否 → 先合并，再删。

---

## 6. 写作风格

| 要求 | 说明 |
|---|---|
| 先给结论 | 每节开头一句结论，再展开论据 |
| 多用表格 | 对比、选型、坑位一律表格化，便于速查 |
| 有取舍 | 不要只写"可以用 X"，要写"X 适合……但代价是……" |
| 有锚点 | 每个技术点都要能落到「本仓库哪一行代码」或「哪个接口」 |
| 不吹 Numbers | 没有来源的性能数字不要写；确实需要时用「数量级」表述并标注为估算 |
