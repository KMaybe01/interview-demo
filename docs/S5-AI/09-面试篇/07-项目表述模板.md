## 1. 你的"项目"从哪来

没有公司级 AI 项目也能讲得有血有肉，因为 `apps/ai-course` 本身就是**一条完整的工程链路**：

| 你做过的事 | 对应关卡 | 可讲的技术点 |
|---|---|---|
| 流式聊天（中断/重连/成本可见） | ① | SSE 分帧、TTFT、parts 渲染、AbortSignal |
| 知识库问答 + 溯源 + 评测 | ② | 分块、混合检索、Rerank、Recall@K |
| 带审批的 Agent | ③ | 工具契约、停止条件、HITL 工单 |
| 网关容灾 / 护栏 / 可观测 | ④ | 熔断 5 次/30s、注入检测、PII 脱敏、trace |
| MCP 服务 + A2A 协作 | ⑤ | 无状态端点、幂等、MRTR、任务状态机 |
| 生成式 UI | ⑥ | 组件白名单、递归校验、XSS 边界 |

> 讲的时候别背"我做了个 AI 应用"，要讲**你在某一关解决的具体矛盾**。矛盾越具体，可信度越高。

## 2. 简历 bullet 模板

用「动作 + 约束 + 结果」三段，避免形容词：

```
句式：为了解决 <约束/风险>，我 <做了什么>，把 <指标> 从 X 降到 Y。
```

| 关卡 | 示例 bullet |
|---|---|
| ① | 为解决长回答的等待体验问题，实现 SSE 流式链路与客户端分帧解析，首字延迟从 3.2s 降到 0.8s，并支持中途中断（服务端同步中止生成） |
| ② | 为解决"模型不知道公司内部知识"，搭建 RAG 链路（分块 + BM25/向量混合检索 + 引用溯源），并在 40 条标注集上把 Recall@5 从 0.61 提到 0.83 |
| ③ | 为防止 Agent 乱执行不可逆操作，设计工具副作用分级（L0/L1/L2）与审批工单（TTL 10min），不可逆操作 100% 经人工确认，审计覆盖四种拦截 outcome |
| ④ | 为应对厂商限流/故障，实现主备降级链 + 熔断（5 次失败 / 冷却 30s / 半开探测）+ 离线兜底，降级态在 UI 显式标注 |
| ⑤ | 把内部能力按 MCP 2026-07-28 无状态单端点暴露（幂等键 + MRTR + 双版本兼容），并用 A2A 任务状态机串联两个专有 Agent |

> ⚠️ 数字要真实。没有就写"在 X 条评测集上从 A 提到 B"这种可复现口径，别编 QPS/PV。

## 3. STAR 讲法（每个项目准备 2 分钟版）

| 段 | 讲什么 | 反面 |
|---|---|---|
| **S 情境** | 业务背景 + 为什么必须做（一句） | 长篇业务介绍 |
| **T 任务** | 你负责的边界（明确"我"） | 说"我们团队"然后再也回不到"我" |
| **A 行动** | **取舍**：为什么选 A 不选 B | 罗列技术名词 |
| **R 结果** | 指标 + 上线后发生了什么 + 有没有翻车 | 只有"效果很好" |

**加分项：主动讲一次失败。**
例如："第一版把 Top-K 设成 20，召回是高了，但答案质量反而下降且成本翻倍——后来才明白噪声进入上下文会干扰模型，最终降到 5 并配合 Rerank。"

面试官听到的不是你踩过坑，而是你**有判断依据**。

## 4. 高频追问与答题骨架

> **"你这个和直接调 API 有什么区别？"**
> 直接调 API 解决"能生成"，我解决的是"能上线"：流式体验、成本控制、失败降级、注入防护、可观测、可回滚的 Prompt 版本。

> **"为什么不用 LangChain / 用什么框架？"**
> 用户侧 UI 与流式用 AI SDK（和 React 心智一致）；后端重编排用本仓库 Go 实现。选框架看的是**团队栈和要解决的问题**，不是流行度。

> **"你怎么证明改动没有让效果变差？"**
> 评测集 + CI 门禁：固定数据集跑四指标（Faithfulness / Relevancy / RetrievalHitRate / ContextPrecision），跌破阈值 PR 失败。并说明当前指标是**词典重合度代理值**，适合看趋势、不适合对外承诺。

> **"模型厂商挂了怎么办？"**
> 主 → 备 → 离线兜底；熔断 5 次失败 / 冷却 30s / 半开放行 1 次探测；降级响应带 `degraded` 标记并在 UI 显式提示。

> **"Prompt 注入怎么防？"**
> 先说根因（指令与数据同通道，无法彻底消除），再说分层：规则检测 + 脱敏 + 工具权限分级 + 人工审批 + 审计。并主动说明流式输出护栏是常见欠账。

> **"成本怎么控？"**
> 三层：模型分层（简单任务不上旗舰）、缓存（前缀要稳定）、配额与步数上限（Agent 的硬边界）。并说明估算价与真实价要区分（本仓库 `Estimated` 字段）。

## 5. 反问清单（把面试变成双向选择）

| 问 | 能探出什么 |
|---|---|
| 线上 Agent 的平均步数和停止原因分布是多少？ | 有没有真的可观测 |
| Prompt 改动怎么发布和回滚？ | 有没有版本化与灰度 |
| 一次会话的成本是怎么统计的？有没有配额？ | 成本治理成熟度 |
| 有没有评测集？PR 会不会跑？ | 工程化程度 |
| 工具调用里哪一类需要人工审批？ | 安全意识 |
